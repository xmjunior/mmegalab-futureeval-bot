# API grant experiment

The primary panel and its reference probabilities were frozen before inference. All arms receive the identical UTF-8 contents of common-prompt.txt, one request for four binary outcomes. The prompts contain independent US Treasury observations. The cases are correlated. Score each binary outcome after the stated publication lag and report paired Brier and log loss; four observations cannot establish general forecast superiority.

The included treasury-asof.csv is the normalized date/10Y/2Y subset through 23 November from the Treasury XML digest recorded in panel.json. One unit test reconstructs all four reference probabilities from those rows. This archive is for replication only. The model takes only the common prompt as input. Outcomes or forecasts issued after the published 24 November cutoff are ineligible for this panel.

Run the standard-library checks from the checkout.

    python -m unittest discover -s research/promo -p test_runner.py -v
    python research/promo/runner.py dry

The grant arm uses the explicit GPT-5.6 Sol model on OpenAI's global standard Responses endpoint. The reviewed model price is US$4 per million input tokens and US$20 per million output tokens. The exact count endpoint includes formatting tokens and is free. For one full-panel request the hard ceilings are 2,048 input tokens and 448 total generated tokens including hidden reasoning. The conservative budget charges both token categories at US$20/M. Maximum reservation **US$0.04992**, within the US$5.50 grant-only ceiling. The model gets no tools, no files, no prior conversation, no web, no fast or regional routing, and no retries. A changed official price, mismatched model or ambiguous request is recorded. An incomplete or empty response still records available token counts, model, reasoning-token count and a hashed receipt ID. The full reservation remains spent for the local safety budget even on failures. All usage awaits grant-level reconciliation with the billing statement.

The private scope is loaded only in memory from OPENAI_PROMO_VERIFIED_AUDIT. Secret keys belong in CI. No evidence record is requested from the user by this runner. One positive promotion and a separately identified purchased balance are compatible. In that case the account must hold the complete inference reserve plus an additional full reserve in that promotion, with concurrent usage isolated and the balance checked within 30 minutes. Neither a positive unclassified balance nor a second eligible promotional balance passes automatically. In an organization with multiple live promotional grants, the support articles guarantee promotional-before-purchased ordering only. In that case this runner requires a reviewed implementation of the provider's documented grant-level attribution before enabling use.

## ARENA blinded historical cohort

`python research/promo/closed_cohort.py dry` scores the frozen Beta(2,2) and 50% references on 12 disjoint five-observation Treasury horizons. Each model call receives only one origin's prior counts and recent changes. Asset identity, dates, absolute levels and outcomes stay out of the prompt. The source was already public. This is a retrospective ablation and does not eliminate possible training-data overlap. No submitted competition question is involved.

The `verify/arena-account-activity` workflow reads organization costs using an existing credential through the official [Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs). A successful read describes posted usage. Pending and concurrent charges require a separate upper bound because the provider will [use purchased credits after promotions run out](https://developers.openai.com/api/docs/guides/chatgpt-api-credits). It logs no account-level amounts or identifiers.

The `verify/arena-closed-grant` workflow reproduces the baselines and runs the model only when the original project's key and a reviewed organization-wide exposure bound are available. The private `ARENA_EXPOSURE_RECORD` binds `org` and `project` to the previously verified `snapshot_sha256`, `covered_from`, `valid_through`, `verified_orgwide_including_pending` and `external_upper_micro_usd`. Its digest goes in `ARENA_EXPOSURE_SHA256`. The bound must include all usage outside the journal that could debit the verified grant, including unposted requests and draws through the execution window. A digest identifies the inspected record; it does not establish the accuracy of its financial evidence.

Before any inference, the existing Git compare-and-swap journal reserves every request's maximum including hidden reasoning, with previous and ambiguous reservations fully retained. The arm stops on a transport/contract failure and never repeats the cohort. Each result includes the input hash, model receipt, paired outcome and score. The script uses the verified original grant floor, authorized cumulative cap and an expiry of 26 November 00:00 UTC. Pending service-level attribution remains separate from local budget accounting.

The owner can also confirm a single, bounded execution using the same repository secret used in run 45493080434. Commit the reviewed code first. Only after receiving the account owner's confirmation, add one file, `research/promo/owner-window.json`, in a direct child commit. Its fields are `study`, `reviewed_code_sha` (the parent), the original `snapshot_sha256`, `prior_run_id` (string), `attested_at`, `valid_through`, `verified_orgwide_including_pending` and a conservative `external_upper_micro_usd`. This last value can be rounded upwards to avoid revealing the owner's actual usage. It must bound unjournaled debits from the original verified snapshot, including earlier unposted charges and all other draws until the end of the window. Use explicit UTC offsets. Push the authorization commit to `verify/arena-closed-grant`. The runner verifies the immutable parent, sole changed path, canonical repository, push attempt, cutoff and original provider receipt before inference. This path omits account identifier headers and uses the same canonical project-secret binding as the original invocation. The default repository intentionally contains no owner-window record.
